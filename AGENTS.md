# AGENTS.md — MongoDB Controllers for Kubernetes (MCK)

Notes for AI coding agents and new contributors. This file lists **only the things where
the obvious default is wrong here**. Everything else works the way you'd expect.

Background reading, not repeated below: [CONTRIBUTING.md](CONTRIBUTING.md),
[E2E test framework](docker/mongodb-kubernetes-tests/README.md),
[Kubernetes version support](docs/dev/kubernetes-version-support.md).

## Things that fail silently

Read this section before anything else. Each of these produces a green build or a clean
run while doing the wrong thing.

### A new e2e test that isn't wired up "passes"

Evergreen runs the suite as `pytest -m $TASK_NAME`, so the `@pytest.mark.e2e_<name>`
marker must match the Evergreen task name **exactly**. `pytest.ini` declares no `markers`
list and sets `filterwarnings = ignore::UserWarning`, so a typo produces no warning —
pytest collects **0 tests** and the task goes green.

Wiring a new test requires, in lockstep:

1. `@pytest.mark.e2e_<task_name>` on the test.
2. A task in **`.evergreen-tasks.yml`** (hand-written, no generator).
3. That task added to a task group / buildvariant in **`.evergreen.yml`**.

Note the tests README still calls these files `evergreen.yaml`; the tasks now live in
`.evergreen-tasks.yml`. Verify the wiring — this prints the variants that will run it, and
prints **nothing** for a name that isn't wired:

```bash
PYTHONPATH=. python scripts/python/find_test_variants.py --task-name e2e_my_test
```

### Duplicate fixture filenames shadow each other, warning suppressed

`kubetester.fixture()` / `yaml_fixture()` searches every `fixtures/` directory recursively
and, on a duplicate filename, warns and returns the **last** match
(`docker/mongodb-kubernetes-tests/kubetester/kubetester.py:1644`). That warning is a
`UserWarning`, which `pytest.ini` suppresses. Give new fixture files distinctive names.

### `make precommit` rewrites tracked files — re-stage afterwards

It is not a read-only check. `.pre-commit-config.yaml` runs a **serial priority chain**;
don't reorder it or run hooks individually:

| Priority | Writes |
|---|---|
| P1 | `release.json`, `config/crd/bases/*`, `helm_chart/crds/*`, `.evergreen-mco.yml` |
| P2 | `release.json` (propagates `mongodbOperator`) |
| P3 | `helm_chart/values.yaml` |
| P4 | `public/mongodb-kubernetes*.yaml`, `config/manager/manager.yaml`, `config/rbac/*` |
| P6 | read-only lint (`black`, `isort`, `shellcheck`, `golangci-lint`, `ty`, validators) |

Consequence: **hand-editing versions in `helm_chart/values.yaml` or `release.json` is
overwritten.** Bump through the P1/P2 scripts
(`scripts/evergreen/release/update_release.py`, `update_mongodb_operator_version.py`).

`make precommit-full` additionally sets `MDB_UPDATE_LICENSES=true` and
`MDB_REGENERATE_RBAC=true`; plain `make precommit` skips both
(`scripts/evergreen/check_precommit.sh`).

### RBAC is not regenerated by `make manifests`

Adding a `+kubebuilder:rbac` marker or a newly watched type also needs:

```bash
scripts/dev/generate_files.sh regenerate_public_rbac_multi_cluster
```

which runs `n="true" go test ./... -run TestPrintingOutRolesServiceAccountsAndRoleBindings`
to rewrite `public/samples/multi-cluster-cli-gitops/resources/rbac/*.yaml`. In precommit it
only runs when `MDB_REGENERATE_RBAC=true`, but the `check-kubebuilder-annotations` hook (P1)
will catch drift. `helm_chart/templates/operator-roles-*.yaml` are **hand-written** and must
be kept in sync with the markers manually.

### A new Go dependency needs regenerated licenses

`scripts/evergreen/update_licenses.sh` rewrites three committed `LICENSE-THIRD-PARTY`
files (repo root, `cmd/kubectl-mongodb/`, `mongodb-community-operator/cmd/readiness/`).
Skipping it fails CI.

### `go test ./...` skips the community e2e suite

Those tests are behind `//go:build community_e2e` (`mongodb-community-operator/test/e2e/`).

## Bootstrap and Python

- `scripts/dev/set_env_context.sh` **hard-fails** without `.generated/context.export.env`.
  Run `scripts/dev/switch_context.sh` (or `make switch context=<ctx>`) first — most make
  targets and every python script are dead until then. `PYTHON_VERSION` comes from it.
- The venv is **`./venv`, not `.venv`** (override with `PROJECT_VENV_PATH`), created with
  **uv**, not pip, by `scripts/dev/recreate_python_venv.sh`. Don't create a `.venv` — it
  will be silently ignored while you think it's active.
- That script appends `OPENSSL_CONF=/dev/null` to the venv's `activate`. Don't strip it.
- Don't call `pytest`/`python` directly for repo scripts: `scripts/dev/run_python.sh`
  requires an active venv, sets `PYTHONPATH`, and hard-fails on an exact `python --version`
  mismatch against `PYTHON_VERSION`. Use `make python-tests` for unit tests.
- `make golang-tests` runs `go tool gotestsum` (JUnit output). Plain `go test ./...` is fine
  locally — there is a single root `go.mod` covering `mongodb-community-operator/`.

## Never hand-edit — regenerate instead

| Path | Regenerated by |
|---|---|
| `config/crd/bases/*.yaml`, `helm_chart/crds/*`, `public/crds.yaml` | `make manifests` (via `.generated/crd.sentinel`) |
| `*/zz_generated.deepcopy.go` | `make generate` |

| `public/dockerfiles/**` | `scripts/copy_dockerfiles_for_release.py` — edit sources under `docker/` |

## E2E test conventions

- Most fixtures, including `namespace`, are `scope="module"`
  (`docker/mongodb-kubernetes-tests/tests/conftest.py`): **every test in one file shares a
  namespace and runs as an ordered sequence**. There is no `pytest.mark.order`; inserting a
  test mid-file can break the ones after it.
- `pytest.ini` sets `-x`, so the first failure aborts the rest of the file.
- Per-directory `conftest.py` files auto-inject the `default_operator` fixture via
  `pytest_runtest_setup` — the operator is installed even if your test doesn't ask for it.
- Multi-cluster tests are separated by **directory** (`tests/multicluster*`), not by marker;
  topology is detected at runtime.
- Reuse `kubetester/` rather than the raw Kubernetes client: `MongoDB` /
  `MongoDBOpsManager` (`from_yaml`, `assert_reaches_phase`), `KubernetesTester`,
  `MongoTester`, `OMTester`, `Phase`, `Operator`, `certs.py`, `MultiClusterClient`,
  `yaml_fixture`.
- `make e2e` resets the cluster and rebuilds+pushes images — don't run it casually. Image
  builds need `make aws_login` first and push to ECR (see `build_info.json`), not local
  Docker; dev tags default to `$(USER)-dev`.

## Go conventions

- **Env vars**: use `pkg/util/env` (`Read`, `ReadOrDefault`, `ReadBoolOrDefault`,
  `ReadOrPanic`). Raw `os.Getenv` is `forbidigo`-linted. Put names in `pkg/util/constants.go`.
- **Kubernetes objects**: compose with the existing builders — `pkg/statefulset`
  (`Apply`/`Modification`), `pkg/kube/container`, `pkg/kube/podtemplatespec`,
  `pkg/kube/service`, `pkg/util/merge` — not raw structs.
- **New operator setting** = two edits: `helm_chart/values.yaml` **and** the env block in
  `helm_chart/templates/operator.yaml`. There is no automatic mapping.
- **Multi-cluster**: use `pkg/multicluster`. `MemberCluster.Index` drives StatefulSet
  naming. Single-cluster mode still goes through the cluster map via a synthetic
  `__default` entry, so write one code path for both. Member clusters are read from a
  ConfigMap **at operator startup only** — no live reload.
- **Static vs non-static architecture**: `pkg/util/architectures` —
  `IsRunningStaticArchitecture`, and `GetMongoVersionForAutomationConfig` appends `-ent` in
  static mode only. The `mongodb.com/v1.architecture` resource annotation overrides
  `MDB_DEFAULT_ARCHITECTURE`. Code touching versions or images must work in both modes.
- **New multi-cluster reconciler work** should follow AppDB
  (`controllers/operator/appdbreplicaset_controller.go`) or sharded
  (`ShardedClusterReconcileHelper`). Do **not** use
  `mongodbmultireplicaset_controller.go` (`mdbmulti`) as a template.
- `mongodb-community-operator/` is the Community operator consolidated into this repo
  (EOL Nov 2025, see [migration guide](docs/migration/community-operator-migration.md)).
  MCK is canonical; there is no upstream sync.
- `release.json` is the source of truth for image/agent/Ops Manager versions;
  `kubernetes-versions.json` for supported Kubernetes versions
  (`make check-kubernetes-versions`).

## Changelog

`changelog/YYYYMMDD_<kind>_<title>.md` — **underscores**, `kind` one of
`prelude|breaking|feature|fix|other`, title ≤ 50 chars, and the frontmatter `kind`/`date`
must match the filename (`scripts/release/changelog.py`). Generate it:

```bash
python3 -m scripts.release.create_changelog --kind fix "Short description"
```

Use the `skip-changelog` label for changes with no user-facing effect.
