* **Legacy multi-cluster install removed**: Removed the legacy multi-cluster installation flow; each removal is paired with its replacement. The `kubectl mongodb multicluster setup` and `recover` subcommands are removed — use `kubectl mongodb multicluster generate-member-resources` to render per-cluster RBAC and `kubectl mongodb multicluster generate-member-registration` to produce the per-cluster credential Secret and `MemberCluster` CR; to recover or re-add a member cluster, re-apply both. The legacy member-cluster discovery is removed — the operator no longer reads the monolithic multi-cluster kubeconfig Secret or the `<operator-name>-member-list` ConfigMap, and discovers member clusters exclusively from `MemberCluster` CRs and their credential Secrets. The Helm values `multiCluster.clusters` and `multiCluster.kubeConfigSecretName` (and the kubeconfig volume they gated) are removed as no longer needed; `multiCluster.performFailOver` remains. The separate `mongodb-kubernetes-multi-cluster.yaml` manifest is removed — a multi-cluster install is now the standard install plus the `MemberCluster` CRs. The GitOps recovery-Job sample is removed — recovery is re-applying `MemberCluster` CRs; the sample's member-cluster RBAC YAML remains and is now generated with `generate-member-resources`. Stale CRD comments and validation referencing the removed flow were cleaned up accordingly.
